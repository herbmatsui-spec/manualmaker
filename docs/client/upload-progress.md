# アップロード進捗の表示（P4 ステップ5）

## 表示する進捗

ブラウザーからの送信進捗と、サーバー保存完了・OCR処理進捗は別の指標です。送信100%でも保存成功ではありません。送信後は「保存中」を表示し、HTTP成功応答を受信した後に完了としてください。

実装例は [upload-progress.js](upload-progress.js) です。フォーム形式でPDFを送信し、進捗通知・保存完了通知・失敗通知を分離します。返される中止用関数でユーザー操作によるキャンセルができます。

## 組み込み手順

1. ファイル選択画面に進捗バー、状態表示、キャンセルボタンを用意する。
2. [実装例](upload-progress.js) を読み込み、選択したファイルと画面更新用コールバックを渡す。
3. 合計サイズを取得できないイベントでは不確定の進捗表示にする。
4. 送信完了通知では保存待ち、HTTP成功応答では保存完了を表示する。
5. 413ではファイルサイズを縮小、429では応答の再試行待ち時間に従う。ネットワーク障害時の自動再送は重複保存を生むため行わない。

ブラウザーにフォーム境界と送信長を設定させるため、Content-TypeとContent-Lengthを手動設定しないでください。クロスオリジン利用時にはプリフライトとCORS設定も必要です。進捗イベントの総バイト数にはフォームの付加情報が含まれ、ファイルサイズとは一致しません。

## 制限と検証

- 現在のサーバーはフォームを解析してからR2へストリーム転送します。入力全体が省メモリ化されたわけではありません。100MiBのローカルモック試験成功はCloudflare Workersのメモリ制限下での成功を保証しません。
- ブラウザーで送信をキャンセルしても、既に始まったサーバー保存のロールバックを保証しません。再送前にアップロード一覧を確認してください。
- Fetchの送信ストリームで計測できるのは読み出された量であり、ネットワークへの送信完了や永続化完了ではありません。ブラウザーでの送信進捗表示には今回の方式を推奨します。
- 手動確認：小ファイル、大ファイル、低速接続、合計サイズ不明、キャンセル、413、429、500、ネットワーク切断で表示を確認してください。ブラウザー実機による確認は未実施です。
