# C7 残作業の詳細実装計画

作成日：2026-09-17

## 1. 目的・基準点

[元計画](C7-remaining-plans.md)の未完了部分を、小さな変更と検証の繰り返しで完了させるための実行計画。

直近の確認済み状態は **32ファイル・221テスト成功、型チェック成功**。ドライランビルド成功はP8ラッパー修正前のため、最新変更については再実行が必要。詳細な履歴は[検証記録](C7-validation-log.md)を参照する。この計画書作成時にはテストを再実行していない。

### 再実装しない項目

- P4：ストリーミング・Range・ユーティリティ、クライアント例、ローカル性能比較。
- P7：副バケット設定、R2複製、KVバックアップ・復元、Cron、独立ヘルス検査、手動切替の状態表示。
- P8：基本状態遷移、タイマー解放・時刻0の修正、外部APIラッパーの認証ヘッダー補完、入力別ハッシュキー、開状態での入力別フォールバック。
- P9：現在登録される業務ルートの契約、網羅性テスト、CI設定、利用ガイド。

P1〜P3・P5〜P6は、今回の残タスクとして未完了と確認できていないため、改めて実装対象へ追加しない。周辺機能は回帰テストの対象とする。

### 現在の重要な未完了事項

1. 外部APIプロキシは修正済みラッパーをまだ呼んでいない。
2. 監視コードは存在するが、本番の共通ルート登録に含まれない。単独テスト成功と本番公開は別。
3. 回路の共有範囲、管理認証、キャッシュ保持方針を決めてから本番連携する必要がある。
4. 網羅性テストの成功は、全応答のスキーマ適合やOpenAPI全体の妥当性を保証しない。
5. GitHub CI、SDK生成、実Cloudflare、ブラウザーは未検証。

## 2. 進め方

### 1ステップの作業単位

各IDは原則として「1目的、1〜3ファイル程度、1つの対象テスト群」。大きくなった場合は実装前に枝番へ分割する。表の各行はすべて未着手の実行項目であり、計画書への記載だけで完了とはしない。

1. 対象ファイルの最新差分を確認し、ユーザーや他作業の変更を上書きしない。
2. 不具合修正では再現テストを先に追加し、失敗原因を確認する。
3. 最小限の実装を行う。
4. 対象テストと型チェックを実行する。
5. 失敗があればそのステップ内で修正・再検証する。他の実装へ進まない。
6. 検証記録に変更・実行コマンド・結果・制約を追記する。

**検証の頻度**：各小ステップでは対象テスト、各章の終了時では全テスト。ルート登録・依存更新・エントリーポイント変更後はドライランビルドも実行する。無変更での同じ調査・全テストの反復は避ける。

### 完了の区分

- **実装完了**：対象テストと型チェック成功。
- **ローカル統合完了**：本番アプリ構成の回帰・契約・ビルド成功。
- **運用確認完了**：承認済み実環境で検証証跡を取得。

環境・権限不足は「保留」と記録する。未実施を成功扱いにしない。

## 3. 推奨順序・依存関係

**A → B → C → D → E → F → G → H → I** を基本順序とする。

- A：再現性と最新ビルドを確保。
- B：P8の仕様・安全な運用範囲を決定。
- C：P8の回路・通信・キャッシュ基盤を補完。
- D：P8を本番ルートへ接続し、監視・リセットを公開。
- E：P7の境界・総合シナリオを完了。
- F：P9の最終契約・CI・SDKを検証。
- G：P8の性能評価と運用文書。
- H：承認後の実環境検証。
- I：最終ゲートと元計画の総括。

EはDと独立して進められるが、同じファイルの並行変更は避ける。Fの最終照合はDによる新ルート追加後に行う。Hは承認が得られるまで実行しない。

### 最終受入条件

- 本番プロキシが回路を使用し、同環境の複数要求で短絡・復旧する。
- 管理操作が認証なしで実行できず、リセットの有効範囲を明示する。
- キャッシュが異なる入力/利用者スコープへ混ざらず、無効化できる。
- P7の部分失敗・サイズ上限・非原子的復元・未複製範囲を検証/文書化する。
- 公開APIと契約が一致し、仕様検証と契約テストがCI対象になっている。
- 最新変更で全テスト・型チェック・ビルドが成功する。
- 実環境未検証は残件として表示し、ローカル成功で代替しない。

## 13. ロールバックと作業記録

- 変更単位は本書のIDごと。ユーザーの既存変更を巻き戻さず、対象差分のみ戻す。
- キャッシュ有効化は回路連携と分離する。異常時はキャッシュを無効にし、旧共通キーを再利用しない。
- 回路の緊急無効化を用意する場合、既存レート制限を維持し、上流への過負荷を考慮して操作する。
- 管理認証の障害時に認証を外す回避策は採らない。管理機能を閉じた状態に戻す。
- データ復元は自動ロールバックできる前提にしない。適用前の隔離確認と対象KVの保全を必須にする。
